# 低频工具折叠

每个工具 schema 都是每一步都要付的常驻成本。实测这台机器上 65 个工具里 38 个在整场会话中一次都没被调用，却占掉 55.8% 的工具 schema 字节。

这个插件把这类工具从「完整 JSON Schema」降级成「一行名字 + 一句描述」，挂在 `tool_fold` 下面。

## 怎么用

- `tool_fold({action:"list"})` —— 看折叠了哪些，每条一句描述
- `tool_fold({action:"load", name:"subagent"})` —— 取回来，下一轮开始就是普通工具
- `tool_fold({action:"status"})` —— 折叠了多少 / 取回了多少

## 配方

| 配置键 | 含义 |
|---|---|
| `enabled` | `false` 完全关闭，工具恢复原状 |
| `fold` | 自定义折叠名单；留空用内置默认（远程主机 / 团队任务 / 定时任务 / 子代理编排 / 低频桌面控制） |
| `keep` | 从默认名单里豁免的名字 |

`pwsh`、`read`/`write`/`edit`、`glob`/`grep`、`tool_fold` 等永远不折叠，写进配置也没用。

## 缓存纪律（最重要的一条）

工具清单排在每次请求的**最前面**。因此：

- **只在 agent 的第一步施加一次**，之后整场不再变动。
- **绝不中途增删**。哪怕多藏一个工具看起来更省，它会让整个前缀缓存作废，实际更贵。
- `tool_fold({action:"load"})` 是唯一允许的中途变动，且只该为「马上就要用的能力」付出这一次代价。

早期版本每步都重算目录并重施限制，导致跑着的对话中途被撤走几十个工具、缓存命中率明显下降——这是被修掉的行为，不是设计。



## 安全边界

- 只用 `deny` 过滤，不用 `allow`。写错一个名字的后果是「少显示一个」，不是「全没了」。
- 被折叠的工具仍在注册表里，随时可取回，不改变任何插件的能力。
- 折叠清单在插件加载那一刻拍快照；之后才注册的工具不受影响。
